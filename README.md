# Noriwake — нативный форк Zooshi

Основное направление теперь **полная нативная 3D-игра на основе google/zooshi**,
а не развитие Canvas-макета вместо оригинального движка.

**Статус: исходники перенесены, первые изменения внесены; современный APK ещё
не собирается и на устройстве не проверен. Это НЕ готовый релиз.**

## Что где находится

| Путь | Назначение |
|---|---|
| `native/zooshi/` | Реальный C++/Android source fork Zooshi с оригинальной игровой архитектурой |
| `native/upstream.lock.json` | Зафиксированный commit, хеши файлов и 25 прямых зависимостей |
| `native/zooshi/src/noriwake/session.h` | Новый нативный режим рейса и локальная прогрессия |
| `tools/native.py` | Восстановление ресурсов, проверка происхождения, диагностика сборки |
| `native/README.md` | Как подготовить форк и какие блокеры остаются |
| `src/`, `android/` | Прежний веб-прототип и **его** Capacitor-оболочка, НЕ нативный Zooshi |
| `docs/WEB_PROTOTYPE.md` | Отдельная инструкция для прежнего браузерного прототипа |

Live Preview показывает прежний веб-прототип. Он не запускает C++-игру.
Команда `npm run android:sync` также относится ТОЛЬКО к веб-прототипу.

## Быстрая проверка форка

Python 3.10+; для C++-тестов Linux/macOS с GCC/Clang и поддержкой UBSan.

```sh
python3 tools/native.py verify
python3 tools/test_native.py
python3 -m unittest discover -s native/tests -p 'test_*.py' -v
```

Подготовить оригинальные крупные ресурсы (около 125 MiB загрузки):

```sh
python3 tools/native.py assets
python3 tools/native.py verify --assets
python3 tools/native.py doctor
```

`doctor` сейчас **ожидаемо завершается с кодом 1** и выводит реальные блокеры.
Это не ошибка установки Python и не признак готовой Android-сборки.
Не нужно восстанавливать оригинальный google-services.json или подключать
чужой облачный проект, чтобы скрыть ошибки сборки.

## Что сделано в нативном коде

- Перенесены исходная физика бросков, река/маршруты, животные и анимации,
  квоты по кругам, усложнение, меню, пауза, звук, XP и разблокировки.
  Эти унаследованные механики ещё не проверены запуском в новом окружении.
- Добавлен режим до 90 секунд с сохранением исходного режима Classic.
- Новое переключение режима в Options, таймер и сводка локальных результатов.
- Локальные рекорды, число рейсов и доставок; защита от повторного начисления
  при повторном входе в экран результатов в рамках одного процесса.
- Текстовые сюжетные вехи после 25 и 100 доставок. Это НЕ новые 3D-районы.
- Сохранены лицензии и атрибуция. Измененные upstream-файлы помечены.
- Крупные ресурсы хранятся вне Git; восстановление проверяет каждый Git blob ID.

Новые session/progress и реальные offline-адаптеры сервисов протестированы C++-компилятором с UBSan и через CMake/CTest. Интеграция HUD,
движка и Android **не подтверждена полной компиляцией**.

## Следующий этап

Подготовка полного дерева C++ зависимостей, перенос конвейера ресурсов,
затем реальный запуск Gradle/NDK и исправление ошибок compile/link.
Затем APK-тест на устройстве, собственная графика/брендинг и Solana-интеграция.
Кошелек, cNFT, backend, сетевой лидерборд, ежедневные задания, кланы и PvP
не возникают автоматически от форка и пока не реализованы.

Подробно: [план готовности](docs/NATIVE_RELEASE_PLAN.md),
[лицензии](docs/LICENSING.md), [изменения upstream](native/MODIFICATIONS.md).

## Выполнен следующий этап: offline-основа

- Убраны вызовы/заголовки Firebase, облачная аналитика, remote config и запуск облачного приложения.
- Из Gradle/CMake/NDK убраны прямые cloud/GPG SDK зависимости и линковка.
- Старые сервисные интерфейсы теперь явно недоступны: не выдают награды,
  не симулируют успешный логин/просмотр рекламы и не ожидают сеть бесконечно.
- В исходном manifest больше нет сетевых разрешений, push-сервисов и Google deep links.
- Dev applicationId: `com.noriwake.game.nativepreview`, отдельно от Canvas/Capacitor-прототипа.
- Activity не запускает VR/NFC; в следующей итерации также удалены Cardboard imports и активные VR build paths (см. ANDROID_PORT.md).

Проверено на offline-этапе: 14 Python-проверок, 2 C++ набора с UBSan, 2/2 CTest. Сейчас Python-проверок 21.
Это **не** проверка собранного Android APK или итогового merged manifest.
Подробно: [границы offline-профиля](docs/OFFLINE_NATIVE.md).

Графику не перерисовывали программно. План художественных замен и партии
строго по 10 изображений: [ART_PIPELINE.md](docs/ART_PIPELINE.md).

## Последняя итерация: Java без Cardboard и 64-битная конфигурация

- Удалена VR SDK-зависимость FPLActivity; сохранены SDL, touch/gamepad, аудио и vsync.
- В ndk-build исключены HMD renderer/controller; game/engine используют VR=0.
- Конфигурация закреплена на AGP 8.7.3, Gradle 8.11.1, NDK r28c, SDK 35,
  minSdk 23, arm64/x86_64 и libc++ — **полная сборка ещё не подтверждена**.
- Все 6 настоящих Java-файлов скомпилированы на Android API 35 без VR JAR:
  24 класса, 0 ошибок; предупреждения старых API остаются.
- 21 Python-проверка, C++/UBSan и CTest проходят.
- Правки движка сохранены как воспроизводимые проверяемые overrides,
  а не только в игнорируемой папке dependencies.

Это Java-only проверка, не APK и не запуск на устройстве.
Подготовка: `python3 tools/native.py patches` после загрузки FPLBase.
Подробный текущий статус: [ANDROID_PORT.md](docs/ANDROID_PORT.md).
